# lostpart 0.3.0

**Encontre e recupere partições perdidas — agora com interface gráfica e em português.**

O `lostpart` encontra sistemas de arquivos que continuam no disco mas perderam
a entrada na tabela de partições, e reconstrói essa entrada.  É a ferramenta
para quando uma partição some depois de uma repartição, de um `diskpart` mal
executado, de um instalador que sobrescreveu a MBR, ou de um disco cuja tabela
nunca chegou a ser gravada.

## O que mudou na 0.3.0

Esta versão é sobre **linguagem**.  O lostpart foi escrito em inglês, do
começo ao fim, e quem precisa recuperar uma partição não deveria precisar ler
inglês — nem entender o jargão de disco — para usar a ferramenta.

* **Interface gráfica completa.**  `lostpart grafica` abre um assistente de
  sete telas em Tkinter, sem nenhuma dependência fora da biblioteca padrão do
  Python.  A varredura roda em uma thread separada, então a janela nunca
  congela, e cada tela explica em português o que está acontecendo e o que
  vai acontecer.
* **Tudo em português.**  Não só a interface: também o console, o menu, as
  mensagens de erro e a ajuda da linha de comando.  Os textos vivem num
  catálogo único (`lostpart/i18n.py`), para que o vocabulário seja coerente.
* **Console redesenhado.**  Painéis com moldura, tabelas de colunas
  alinhadas, rótulos e valores alinhados, barra de progresso de uma linha e
  marcadores de sucesso, aviso e erro.
* **Comandos em português.**  `listar`, `escanear`, `recuperar`, `navegar`,
  `backup`, `restaurar` e `grafica` — cada um também aceitando o nome em
  inglês, para que scripts antigos continuem funcionando.

Quando faltam privilégios, uma faixa no rodapé explica isso e oferece o botão
**Executar como administrador**, que reabre o programa já elevado.

No Linux, torne o arquivo executável antes da primeira execução:

```bash
chmod +x lostpart-linux-x64
./lostpart-linux-x64 --help
```

execução e reaproveita essa cópia depois.

Os três artefatos saem da mesma árvore de código e passam pela mesma suíte de

### Instalando no Windows

Rode `lostpart-installer.exe` e siga o assistente.  Ele instala em
`%LOCALAPPDATA%\Programs\lostpart` e pergunta se você quer adicionar o
programa ao PATH.

Se o Windows bloquear o instalador, clique em *Mais informações* e depois em
*Executar mesmo assim*, ou rode a partir de um terminal:

```powershell
Unblock-File .\lostpart-installer.exe
.\lostpart-installer.exe
```

Para conferir o download antes de executá-lo, compare a soma SHA-256 com a
publicada ao lado dos arquivos.

> **Por que o executável não é assinado digitalmente.**  Assinar exige um
> certificado de uma autoridade confiável, o que tem custo.  A mitigação é
> publicar o `SHA256SUMS.txt` junto dos arquivos, e preferir o instalador —
> o programa instalado roda do disco local, sem a marca *Mark of the Web*, e
> nada o bloqueia depois.

## Uso

A partir do instalador, o atalho do menu Iniciar abre a interface gráfica.
Na linha de comando:

```bash
# abrir a interface gráfica
lostpart grafica

# listar os discos e suas partições
lostpart listar
lostpart listar --device 0

# procurar partições perdidas no espaço livre
lostpart escanear --device 0
lostpart escanear --device 0 --mode quick
lostpart escanear --device 0 --json
lostpart escanear --device 0 --checkpoint scan.db

# ver o conteúdo de um candidato sem gravar nada
lostpart navegar --device 0 --start 1048576
lostpart navegar --device 0 --start 1048576 --path "Users/ana"

# gravar a entrada que falta (ensaio por padrão)
lostpart recuperar --device 0 --start 1048576 --size 4194304 --fs ntfs
lostpart recuperar --device 0 --start 1048576 --size 4194304 --fs ntfs --apply

# salvar e restaurar a tabela de partições
lostpart backup --device 0 --output mbr-backup.json
lostpart restaurar --device 0 --backup mbr-backup.json
```

Sem comando nenhum, o programa abre um menu:

```
lostpart 0.3.0 - encontre e recupere partições perdidas

   1  Listar os discos e suas partições
   2  Procurar partições perdidas em um disco
   3  Ver o conteúdo de uma partição
   4  Salvar a tabela de partições de um disco
   5  Abrir a interface gráfica
   6  Mostrar as opções da linha de comando
   0  Sair
```

Imagens de disco funcionam em qualquer lugar onde um disco físico funcionaria,
o que ajuda a testar e a analisar sem risco:

```bash
lostpart escanear --device /caminho/do/disco.img
```

## Por que dá para confiar

Um sistema de arquivos que por acaso tem os bytes `NTFS    ` em algum lugar
não é uma partição.  O lostpart não confia em assinaturas:

* **Todo candidato é analisado por inteiro.**  O bloco de parâmetros do BIOS
  do candidato é validado campo a campo — bytes por setor, setores por
  cluster, contagem de clusters, geometria da FAT, superbloco.  Um candidato
  que falha na validação é descartado, e o motivo é informado.
* **As bordas do NTFS são provadas pelo mapa de alocação.**  O meta-arquivo
  `$Bitmap` de um volume diz exatamente quais clusters estão alocados.  O
  lostpart lê esse mapa e confere com os bytes reais do disco: clusters que o
  mapa chama de *alocados* precisam conter dados, e os que ele chama
  *livres* precisam estar zerados.  Isso confirma o início do volume e
  determina onde ele termina — o último cluster alocado.  Os setores
  *anteriores* ao candidato também são amostrados, para confirmar que não
  pertencem ao volume.
* **Todo veredito vem com as suas evidências.**  Os motivos por trás de cada
  candidato são mostrados, para que você possa decidir se confia nele.

Exemplo:

```
Partições encontradas

  Disco         \\.\PhysicalDrive0
  Tabela        MBR
  Modo          completa
  Tempo         12.4s
  Espaço livre  2 região(ões), 931.4 GB analisados
────────────────────────────────────────────────────────────────
  Início   Setores     Tamanho  Sistema de arquivos  Confiança  Como foi identificada
  ───────  ────────  ─────────  ───────────────────  ─────────  ─────────────────────
   1048576   4194304  128.0 MB  NTFS                   97%  assinatura + bitmap de alocação
```

## Sistemas de arquivos suportados

| Sistema de arquivos | Detecção | Prova dos limites | Navegação |
| --- | --- | --- | --- |
| NTFS | boot sector + BPB | `$Bitmap` conferido com o disco, `$MFT` como contraprova | sim |
| exFAT | boot sector + validação do VBR | comprimento do volume pelo VBR | sim |
| FAT12/16/32 | geometria do BPB + string de tipo | contagem de clusters pelo BPB | sim |
| ext2/3/4 | magic do superbloco + geometria | contagem de blocos pelo superbloco | sim |
| Linux swap | magic e versão do cabeçalho de swap | contagem de clusters pelo cabeçalho | não se aplica (não tem árvore de diretórios) |
| HFS+ | assinatura, versão e magic do volume header | contagem de blocos pelo cabeçalho | melhor esforço |

## Segurança

* **Nada é gravado sem `--apply`.**  Os comandos `escanear`, `listar` e
  `navegar` abrem o dispositivo somente para leitura.
* **Um backup é feito antes de cada gravação** (desligue com `--no-backup`).
* **As gravações são validadas antes** — candidatos sobrepostos ou fora dos
  limites do disco são recusados.
* **A GPT é mantida consistente**: os dois vetores de entradas, os dois
  cabeçalhos e todos os CRCs são reescritos juntos.
* **Na interface gráfica**, o botão de confirmação é o único caminho para a
  gravação, e a opção de backup vem ligada.

O acesso direto ao disco exige privilégios elevados no Windows (executar como
administrador) e `root` no Linux.

## Origem do projeto

Esta é uma implementação independente, em **clean-room**, escrita a partir das
especificações públicas dos formatos:

| Formato | Referência |
| --- | --- |
| MBR / MBR protetora | layout da tabela de partições do IBM PC |
| GPT | UEFI Specification 2.10, seção 5 |
| NTFS | Microsoft [MS-FSCC] e o layout do volume boot sector do NTFS |
| exFAT | especificação do sistema de arquivos exFAT da Microsoft |
| FAT12/16/32 | especificação [MS-FAT] da Microsoft |
| ext2/3/4 | `Documentation/filesystems/ext2` do Linux |
| Linux swap | `Documentation/admin-guide/uses-of-swapon` |
| HFS+ | Apple TN1150, HFS Plus Volume Format |

Nenhum código proprietário foi copiado.  O comportamento foi estudado por fora
— observando o que um gerenciador de partições faz com um disco — e depois
implementado a partir das especificações.
